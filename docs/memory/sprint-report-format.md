# Sprint document formats

## Individual status report (Word, one per sprint)
1. Title: "Scrum Sprint Status Report — Ben Bailor". Then the date, "Sprint N" and "Team member: Ben Bailor (Team GPT Gains)".
2. A reporting note: items are tagged (Individual) or (Team); bracketed blanks mark evidence still to add.
3. A summary paragraph of three to five sentences on what moved this sprint.
4. "Completed this sprint" table with columns Work unit | What I completed (and who did it) | Obstacles encountered | Evidence it's done.
5. "Review feedback incorporated" table with columns Feedback | How this report responds (when feedback was given).
6. "Plan for the next scrum meeting" table with columns Work unit | How I'll know it's done (specific) | Blockers.
7. "Meeting results": date of the meeting with Prof. Glatzer, what was decided, and the next check-in.

## Team work plan (Word)
- Sprint dates (start and end), then a "Necessary work units" table: ID | Name | Priority | Description with a "Done when" | Status | Owner.
- "Potential work units" table: ID | Name | Description.
- Notes: timeline, carry-over from the last sprint, purchases needed.
- IDs continue from the last plan (NLP-09, POT-08 and so on). Never reuse an ID.

## Writing rules
- Never invent results, numbers, commits or dates. Use [____].
- Each "done when" names a count, metric or file.
- Plain, short sentences. No marketing language.
